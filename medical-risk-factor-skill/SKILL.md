# 医学危险因素分析（v1.6）

## 执行顺序
**严格分为五个阶段：①读取与目标提问 → ②变量选择 → ③核查与确认修复 → ④Logistic 方案确认 → ⑤执行与解释。**

| 阶段 | 动作与停止条件 |
| --- | --- |
| 1 读取与目标 | 只解析工作表、表头并计算来源指纹；多表先选表，不自动合并。**必须向用户提问：“你想分析哪个疾病或临床事件的危险因素？研究对象是谁，表中哪一列表示这个结局？”** 等待实际反馈，明确人群、研究问题、结局字段及定义/时间窗，记录 `research_question.json`。不得凭文件名、列名或 AI 推荐代答；目标未确认，不进入变量选择。 |
| 2 变量选择 | 完整展示全部字段，结局沿用阶段1且单独锁定。每列“纳入/不纳入”，默认不选；结局不作为自身解释变量。辅助核查字段须明确授权及用途且不入模。AI 推荐不代替用户决定。全部选择确认后才可核查。 |
| 3 核查与修复 | 仅核查选定解释变量、结局及授权辅助字段。展示实际缺失及按结局分布、疑似缺失码、异常线索和类型候选；提出具体处置、编码/单位/参照组及缺失方案，等待用户确认。再执行授权处理，另存分析集、前后缺失表与日志并复核；仅填完审核表不算修复完成。待溯源问题未解决时停在本阶段。 |
| 4 模型方案 | 暂仅支持**单因素 Logistic + 多因素 Logistic**。列出全部单因素变量、多因素调整集、结局阳性值、类型/单位/参照组、完整案例策略、各模型预计 N/事件数与局限；确认研究设计及独立观测。等待用户确认正式配置，不按单因素 P 值自动筛变量，不提前拟合。 |
| 5 分析与解释 | 方案确认后执行单因素及多因素分析，输出描述表、粗/调整 OR、95% CI、P、实际 N/事件数、森林图和审计记录。**本阶段必须接着解读实际结果**：回答阶段1问题，对照粗/调整估计，解释方向、尺度、精度、警告与局限；不能只交文件或自动草稿。 |

- **一次只处理当前阶段，不跨阶段合并提问、预先统计或执行。** 当前阶段未获所需反馈或未完成校验就停止；完成后报告“阶段 X/5 已完成”及下一阶段入口，再逐层推进。一次“确认”只授权当前呈现的决定，不视为后续阶段确认。
- 已由用户明确提供的信息直接沿用并核实，只问当前阶段缺项。阶段1仍须明确询问并获得目标反馈；不要求用户手写 JSON，由代理据实记录。未来阶段的信息可以暂存，不能跳过该阶段的展示与确认。
- 来源、目标、变量、处置改变须重新核对受影响阶段；未选字段不参与质量判断、清洗或病例删除。

## 运行与读取
在 skill 目录下运行基础命令：
```bash
python scripts/review_workflow.py --input data.xlsx --sheet Sheet1 --outdir output
```
- 不加其他参数：阶段1，生成来源摘要与 `research_question.template.json`，向用户提出目标问题并等待反馈。
- 加 `--research-question output/research_question.json`：验证阶段1后生成阶段2的完整清单及 `interactive_review.html`；等待 `variable_selection_decisions.json`。
- 再加 `--selection-decisions output/variable_selection_decisions.json`：阶段3，仅生成选定范围的核查、缺失表、类型/处理模板及 `interactive_data_quality.html`。
- 再加 `--validate-decisions output/clinical_review_decisions.json`：仍在阶段3，只验证审核；按 [配置结构](references/config_schema.md) 准备并执行用户确认的处理方案，处理完成才进入阶段4。
- 正常路径直接运行脚本；先看标准输出或阶段摘要 JSON。仅在失败、排查规则或修改代码时读源码，不默认加载 README、HTML 源码及全部参考资料。
- 摘要提供阶段、状态、数量、`next_action`、`required_inputs`、`blocking_reasons` 和产物路径。详情按需查 CSV；变量/问题决策沿用精简 v1.4 结构，新增目标指纹；旧决策须绑定并重新确认当前目标，不得直接跳过阶段1。

## 低冗余交付
- 完整审核页面和 CSV 必须覆盖每个原始字段，保留分类、角色、AI 建议及理由；用户可分类批量选择后逐项修改。有原生表单时可替代离线页面，静态 Markdown 不可声称可点击。
- 聊天默认只报告当前阶段、总数/未确认数、分类汇总、关键待确认项及文件入口；不重复全文表格、JSON 或通用理由。用户要求展开时提供完整内容；没有可用审核页面时须在聊天或表格中全量展示。
- 复用有效决策和产物，不重复执行已完成阶段。数据或选择改变须重新核查对应范围；不能只信文件存在或旧摘要，恢复时核对来源/选择指纹，未确定时用脚本验证。

## 按需参考
- 进入阶段3前读 [统计决策](references/statistical_guidance.md)，阶段4–5沿用已读规则。
- 记录目标、执行阶段3处理或准备阶段4配置时读 [配置结构](references/config_schema.md)；配置样例为 `examples/config.example.json`，模板不代表用户确认。
- 写最终报告时使用 `assets/report_template.md`，通用术语集中解释一次，结果只补充特有的编码方向与比较尺度。
- 阶段4用 `python scripts/run_logistic.py --workflow-dir output --prepare-plan` 生成待确认方案，不拟合；阶段5用 `python scripts/run_logistic.py --workflow-dir output --config output/config.json --outdir output/results`。脚本核验前序决定和分析集指纹，不能只用 `confirmed: true` 绕过。

## 不可省略的边界
- 原始文件只读；不擅自修改、插补、删除或按显著性自动筛掉重要混杂因素。处理派生分析集须可追溯。
- 身份字段不作结局/解释变量，不外传标识值或暴露可识别小单元。临床取值相同不等于同一患者，去重需授权标识与访视信息。
- 规则命中只是核对线索；不得按 IQR/3σ 自动删临床极值，不把特殊编码擅自判为缺失。
- 本版只执行独立观测、二分类、完整案例的单因素及多因素 Logistic。不自动插补，不支持 Cox、MI、匹配、聚类、重复测量；遇到不适用数据停下说明，不扩展或偷换算法。
- 观察性关联不等于因果，OR 不等于 RR。失败或未执行的检查/分析必须如实说明，不编造结果。
