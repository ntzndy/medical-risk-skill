# 阶段3：具体证据、用户决定、确认执行

此规则适用于 v1.7.2 本地修订。顺序仍为目标确认、变量选择、选定范围核查；不先做全表清洗。审核页面和后端校验使用同一决定结构，不能靠把 status 改成 reviewed 绕过逐项决定。

## 缺失情况与方法选择

对每个已选解释变量及结局，页面和默认对话仅展示“变量名 / 缺失比例 / xx%”，不逐行显示人数、角色、结局分布或当前方案；总人数、实际空值数及结局分布仍保留在缺失核查文件和审核数据中，按需核对。首尾空格标准化后的空串计为空值；NA/null/999等保留原值，不自动认定为缺失。缺失信息仅在缺失列表展示，不再生成 HIGH_MISSING 或 ALL_MISSING 异常，不在“其他异常与具体情况”中重复列人数及比例。整列为空仍须明确显示100%并取得处理决定。辅助字段可以核查，但不参与病例删除或缺失策略执行。

### 按30%和50%分组填写意见

- 按顺序集中展示 `0% < 缺失比例 < 30%`、`30% ≤ 缺失比例 ≤ 50%`、`缺失比例 > 50%` 三组。恰好30%和50%均归中组；0%另列“无缺失”，无记录时比例不可计算，不归入无缺失组。
- 以实际缺失数和总数比较边界，不使用四舍五入后的展示比例分组。每组逐变量仅列名称与比例，完整数量、结局分布和拟定方案保留在核查文件及审核数据中，不因精简展示而删除。
- 低组按用户要求预填 `multiple_imputation`，这是用户设定的工作流默认方案，不是缺失率足以证明插补适用的统计结论。列表后只设一个可写入意见框，用户填写要改动的变量、处理方式和原因；留空表示不提出例外，不等于已执行插补。
- 中组和高组均不预选方法，各组列表后设一个意见框，用户可写本组统一方式或逐变量处理意见。没有明确意见不能默认排除变量或病例。结局仍禁止直接排除；其缺失定义及插补适用性须单独确认。
- 页面提供“提交缺失处理意见”，保存 `missing_group_feedback` 原文，状态为 `missing_feedback_submitted`。这只提交阶段3的缺失子步骤，不要求此时完成其他异常审核，不授权处理或模型。
- 代理读取意见，仅对本组明确提及的变量或明确授权的整组范围整理为 `missing_decisions`；不将自由文字当作代码、映射或可执行规则。展示具体逐变量方案并获确认后，才能将 `resolved_text` 记为已确认的原文。用户再次修改文字后须重新整理确认。未整理意见会阻止正式质量审核通过。

| 选项 | 适用判断与限制 | 当前执行 |
| --- | --- | --- |
| 删除缺失行：逐模型完整案例 | 评估缺失机制、样本及事件损失、选择偏倚；只按各模型所需字段取完整记录，不做全表统一dropna。不能仅凭缺失比例判定合理性。[S1,S2] | 已实现；须明确确认 |
| 该解释变量不纳入分析 | 用户判断临床必要性和数据可用性；不得仅因缺失自动删重要混杂因素，不适用于结局。[S1,S2] | 已实现，另存分析集，原文件不变 |
| 多重插补 | 结合缺失机制（常见MAR假设）、变量类型、模型相容性、结局及已授权辅助变量，确认插补模型、次数、种子、迭代和诊断；每个插补集拟合后用Rubin法则合并，必要时做MNAR敏感性分析。整列无观测值、结构性不适用、检测界限和结局缺失需专项判断，不能默认普通MICE。[S1,S3] | 可记录选择；尚无MI执行及合并引擎，暂停，不退回完整案例 |
| 核对来源并补录 | 只据真实可核实来源，不猜测。数据变化后重建来源指纹并重审受影响阶段。 | 暂停等待核实和新版来源 |
| 结构性不适用/检测界限，另定方案 | 区分没有测量、无适用意义、低于检出限等；先确认定义、研究人群和适用模型，不统一当普通缺失。[S1,S3] | 暂停，等待专项方案 |

没有实际或确认后缺失时记 no_missing，而不是预选完整案例。仅低于30%组默认拟采用多重插补；中高组不预选，默认及草稿均不代表授权。不同变量的决定须形成相容的最终分析方案：只要任一保留变量选MI/补录/专项方案，当前完整案例执行器就拒绝继续。不能把“默认多重插补”写成“本包已完成多重插补”。

均值、中位数、众数单次填补、缺失类别指示法和LOCF不作为正式关联推断的默认菜单；这些办法可能改变变异或带来偏倚，需要设计相符的专项论证。[S1] 此处不宣称它们在所有研究中一概禁用。

## 特殊编码不单列异常

不再自动识别“疑似缺失码”，不生成 SENTINEL_VALUE、疑似码数量、独立确认表或强制是否缺失问答。不能只是隐藏页面而继续把这类值排除在类型、常量或极端值核查之外。

所有非空原值仍参加常规核查：999可因实际分布触发极端值，NA与数字并存可触发类型混杂；不因其属于固定编码名单而跳过。若用户或数据字典明确说明某变量的具体编码表示缺失，代理据实际反馈准备精确set_missing规则并确认后执行；不跨变量套用其含义，执行后重新报告新增缺失并确认处理方式。取消异常类型不授权删除记录、设缺失或认定这些值均有效。

## 混杂、极端值及其他问题

- 数字和非数字同时存在即报告混杂，不因文字比例低而略过。展示数值/非数值数量、文字类别、实际形式及频数，如 `<0.1`、`12mg/L`、`阴性`。用户提供变量含义、保留类型、明确映射/单位规则或其他处置；不自行去掉比较符号、抽取数字或转空。
- 极端值列出变量、Q1/Q3/IQR、上下界、实际最小/最大值、异常值及频数。IQR规则只是线索，不自动删、截尾、缩尾或改值；用户确认真实值可保留，错误值须来源依据和具体规则。
- 负数、非有限值、常量等列具体取值及数量。重复标识只列涉及记录数、组数等汇总，不导出身份值；临床值相同不证明同一患者，不自动去重。
- 常规值列表最多展示20种并注明省略数；敏感/长文本隐藏，不在聊天暴露身份或可识别小单元。页面为本地离线审核，不向外传患者数据。
- 每条其他异常均须用户给出处置意见及理由。选择修改/排除，还需可执行具体规则；当前执行器不能执行的处理方式应暂停说明，不以自由文本“已处理”替代真正执行。

## 执行和复核

缺失表中“该解释变量不纳入”生成排除变量操作。设缺失、映射、换算、按值排除记录等由代理依据用户实际反馈生成processing_plan，展示并确认后执行；不存在疑似编码自动转换步骤。

类型转换仍需确认；不静默把非数字转空。每项改值有日志，原文件只读。处理后重算缺失表并复核异常；具体取值、阈值等证据变化时也需复核，不能只比较影响数量。新产生的缺失必须再次呈现数量及方式，不能用先前“无缺失”授权完整案例，也不能仅用通用残留问题接受项绕过。已明确选择保留、证据未变且没有加重的线索无需反复询问。
